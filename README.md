## Disclaimer

This repository contains **known, deliberately planted security vulnerabilities**. That's on purpose.

- **Don't** install it, run it on untrusted input, or copy its code into a real project. A crafted YAML file can run arbitrary code on any machine that validates it with this tool.
- **Don't** report these vulnerabilities as security issues. They are known and intentional.
- The outdated dependency versions in `requirements.txt` are pinned on purpose. GitHub security alerts on this repo are expected.
- The `patchswarm/*` branches and pull requests are generated by PatchSwarm during demos. The `master` branch is kept vulnerable so the demo can be repeated.
- The exploit used against this code runs only inside isolated Daytona cloud sandboxes, never on a real system.

## Why this repo exists

PatchSwarm needs a safe, legal target that it is allowed to attack. Running real exploits against someone else's code, or against a live project, isn't acceptable. So I built this small repo myself to be attacked.

It's designed to look like the kind of code PatchSwarm is meant to help with: a small internal tool that works fine, has tests that pass, and has quietly fallen behind on security updates. Two things make it a good test case:

1. **A real, exploitable flaw.** It parses untrusted input with an unsafe PyYAML call on a version with a known code-execution bug, so PatchSwarm can *prove* the vulnerability with a real exploit and then prove the fix works.
2. **Scanner noise.** Its old `requests` version also has CVEs that a scanner will flag, even though nothing shows them to be reachable here. That shows the problem PatchSwarm solves: a scanner reports 5 CVEs, and PatchSwarm proves that 1 is exploitable and fixes only that one.

Because the repo is mine, PatchSwarm can push fix branches and open pull requests here without touching anyone else's project.

## What configlint does

configlint is a tiny Python tool that validates YAML deploy manifests submitted by users (`service`, `image`, `replicas`) before they reach a cluster.

## The planted vulnerability

| | |
|---|---|
| **CVE** | [CVE-2020-14343](https://github.com/advisories/GHSA-8q59-q68h-6hv4): PyYAML arbitrary code execution |
| **Where** | `configlint/loader.py`: `yaml.load(text, Loader=yaml.FullLoader)` |
| **Why it's exploitable** | `requirements.txt` pins `PyYAML==5.3.1`. Before 5.4, `FullLoader` can build arbitrary Python objects, so a crafted manifest can run code on the machine that validates it. |
| **Fix** | `yaml.safe_load(text)` and `PyYAML>=6.0.2` |

`requests==2.25.1` also has 4 known CVEs. PatchSwarm flags them as unverified because no proof-of-concept here shows them to be reachable.

## What PatchSwarm does with this repo

1. Finds the 5 dependency CVEs.
2. Runs a real exploit against `load_manifest()` in a Daytona sandbox and proves CVE-2020-14343 executes code.
3. Pushes the fix to the branch `patchswarm/cve-2020-14343`.
4. Re-runs the exploit on that branch: it's blocked, and the tests below still pass.
5. Has a Qwen model on Nosana review the diff, then opens a PR once a human approves.
